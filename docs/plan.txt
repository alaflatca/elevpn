진행 상태 요약
================

완료
----

1. peer handshake와 tunnel IP 할당

    client는 ALOHA에 client random을 포함해 보낸다.
    server는 peer를 등록하고 tunnel IP, MTU, server random을 WELCOME으로 보낸다.
    WELCOME payload는 protocol/payload.go에서 encode/decode한다.
    동일한 client random으로 ALOHA가 다시 오면 기존 peer를 반환해 중복 등록을 막는다.


2. peer lifecycle

    client는 10초마다 KEEPALIVE를 보낸다.
    server는 peer의 lastSeen을 갱신하고 30초 이상 응답 없는 peer를 제거한다.
    peer 제거 시 byID, byTunnelIP, byClientRandom을 함께 정리한다.


3. full-tunnel route와 SSH bypass

    client는 VPN server endpoint와 현재 SSH remote IP에 /32 bypass route를 먼저 추가한다.
    SSH remote IP는 NETLINK_SOCK_DIAG/INET_DIAG로 탐지하며 SSH_CLIENT 환경변수에 의존하지 않는다.
    이후 default route를 tun0로 변경하고 종료 시 기존 route를 복원한다.


4. sliding replay window

    client와 server는 각 방향의 송신 sequence를 독립적으로 증가시킨다.
    수신 측은 64bit replay window로 UDP packet의 순서 역전을 허용하면서 중복 packet을 거부한다.
    direction과 sequence를 AES-GCM nonce로 사용한다.


5. AES-GCM AEAD 암호화

    PSK에서 master key를 파생한다.
    client random으로 ALOHA key를, client/server random으로 WELCOME key를 만든다.
    peer ID, client random, server random으로 DATA와 KEEPALIVE에 사용할 peer key를 파생한다.
    message header는 AAD로 인증하고 payload는 AES-GCM으로 암복호화한다.

    DATA packet 구조:

        [header 20bytes][encrypted payload variable][AEAD tag 16bytes]

    ALOHA packet 구조:

        [header 20bytes][client random 16bytes][encrypted payload][AEAD tag 16bytes]

    WELCOME packet 구조:

        [header 20bytes][server random 16bytes][encrypted payload][AEAD tag 16bytes]


6. AEAD MTU 적용과 packet 검증

    outer IPv4 path MTU 1500을 기준으로 TUN MTU와 MaxPayloadSize를 1436으로 설정했다.
    EC2에서 VPN 서버를 통해 외부 IP로 접속하는 흐름을 검증했다.
    tcpdump로 tun0의 평문 packet과 실제 NIC의 암호화된 UDP packet을 비교했다.


7. 오류 처리와 cleanup

    버려도 되는 packet 오류와 tunnel을 종료해야 하는 I/O 오류를 구분한다.
    TUN, route, IP forwarding, nftables masquerade를 적용 역순으로 정리한다.
    TUN read는 non-blocking fd, poll, eventfd를 사용해 context 취소 시 종료한다.


8. unit test와 동시성 검증

    protocol encode/decode, ALOHA/WELCOME, AEAD round trip을 검증한다.
    잘못된 PSK, packet 변조, direction 불일치의 인증 실패를 검증한다.
    ReplayWindow의 정상 sequence, 중복, window 범위와 이동을 검증한다.
    PeerStore의 등록, 조회, tunnel IP, 만료 삭제, 동시 등록을 검증한다.
    protocol과 server package를 race detector로 검증했다.


남은 작업
---------

1. route rollback 보강

    Route.Apply 중 bypass route를 여러 개 추가하다가 중간 실패하면,
    이미 추가된 route만 내부에서 rollback하도록 보강한다.
    route 적용과 rollback에 대한 unit test를 추가한다.


2. client/server 처리 test

    handshake, sequence 검증, packet drop 처리를 단위 테스트한다.


3. end-to-end test

    Linux network namespace를 사용해 TUN, route, UDP tunnel, cleanup을 자동 검증한다.


4. handshake 보호 보강 (선택)

    활성 peer의 동일한 client random은 중복 등록되지 않는다.
    추가로 짧은 시간의 ALOHA 반복 요청을 제한하는 rate limit을 검토한다.


5. key rotation/rekey (장기 개선)

    장시간 유지되는 peer session의 key를 교체하는 정책을 검토한다.
