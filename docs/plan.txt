진행 상태 요약
================

완료
----

1. WELCOME payload encode/decode 분리

    protocol/payload.go에 WelcomePayload를 추가했다.
    server는 EncodeWelcomePayload를 사용해 WELCOME payload를 만든다.
    client는 DecodeWelcomePayload를 사용해 tunnel IP와 MTU를 읽는다.


2. keepalive 기본 흐름

    client는 주기적으로 KEEPALIVE message를 보낸다.
    server는 KEEPALIVE를 받으면 peer lastSeen을 갱신한다.


3. peer lifecycle 기본 흐름

    lastSeen 기준으로 오래 응답 없는 peer를 제거한다.
    peer 제거 시 byID, byTunnelIP를 함께 정리한다.
    expirePeersLoop는 server.runTunnel의 errgroup 안에서 errCtx로 실행한다.

    기준값:

        client keepalive interval = 10s
        server peer timeout       = 30s
        server cleanup interval   = 10s


4. 에러 처리 정책 정리

    drop 가능한 packet과 tunnel 전체를 종료해야 하는 fatal error를 구분한다.
    decode 실패, unknown message type, peer not found 같은 상황의 처리 기준을 정리한다.


5. route/full-tunnel 정책 정리

    client는 VPN server endpoint를 /32 bypass route로 먼저 추가한다.
    현재 SSH 접속자의 공인 IP도 NETLINK_SOCK_DIAG/INET_DIAG로 탐지해 /32 bypass route로 추가한다.
    이후 default route를 tun0로 변경해 나머지 트래픽을 tunnel로 보낸다.

    적용 순서:

        1. server endpoint /32 route 추가
        2. SSH remote IP /32 route 추가
        3. default route를 tun0로 replace

    정리 순서:

        1. default route를 기존 gateway/interface로 복구
        2. bypass route 삭제

    이 방식으로 sudo 실행 시 SSH_CLIENT 환경변수에 의존하지 않아도 SSH 접속을 유지할 수 있다.


남은 작업
---------

1. 인증/암호화 추가

    현재 UDP payload는 평문이다.
    먼저 pre-shared key 기반 인증 또는 HMAC을 추가한다.
    이후 AEAD 기반 암호화를 검토한다.


2. 운영/테스트 문서 보강

    실행 전 요구사항, 테스트 명령어, cleanup 확인 방법, known limitations를 정리한다.
    가능하면 나중에 EC2 또는 Linux network namespace 기반 통합 테스트도 추가한다.


3. route rollback 보강

    Route.Apply 중 bypass route를 여러 개 추가하다가 중간 실패하면,
    이미 추가된 bypass route만 내부에서 rollback하도록 보강한다.
