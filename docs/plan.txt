진행 상태 요약
================

완료
----

1. peer handshake와 tunnel IP 할당

    client는 ALOHA에 client random을 포함해 보낸다.
    server는 peer를 등록하고 tunnel IP, MTU, server random을 WELCOME으로 보낸다.
    WELCOME payload는 protocol/payload.go에서 encode/decode한다.


2. peer lifecycle

    client는 10초마다 KEEPALIVE를 보낸다.
    server는 peer의 lastSeen을 갱신하고 30초 이상 응답 없는 peer를 제거한다.
    peer 제거 시 byID와 byTunnelIP를 함께 정리한다.


3. full-tunnel route와 SSH bypass

    client는 VPN server endpoint와 현재 SSH remote IP에 /32 bypass route를 먼저 추가한다.
    SSH remote IP는 NETLINK_SOCK_DIAG/INET_DIAG로 탐지하며 SSH_CLIENT 환경변수에 의존하지 않는다.
    이후 default route를 tun0로 변경하고 종료 시 기존 route를 복원한다.


4. sequence 기반 replay 방지

    client와 server는 각 방향의 송신 sequence와 마지막 수신 sequence를 별도로 관리한다.
    수신 sequence가 마지막으로 수신한 값보다 작거나 같으면 replay packet으로 버린다.
    direction과 sequence를 AES-GCM nonce로 사용한다.


5. AES-GCM AEAD 암호화

    PSK에서 master key를 파생하고 client random으로 handshake key를 만든다.
    peer ID, client random, server random으로 peer별 key를 파생한다.
    ALOHA와 WELCOME은 handshake cipher를, DATA와 KEEPALIVE는 peer cipher를 사용한다.
    message header는 AAD로 인증하고 payload는 AES-GCM으로 암복호화한다.

    DATA packet 구조:

        [header 20bytes][encrypted payload variable][AEAD tag 16bytes]

    ALOHA packet 구조:

        [header 20bytes][client random 16bytes][encrypted payload][AEAD tag 16bytes]


6. 오류 처리와 cleanup

    버려도 되는 packet 오류와 tunnel을 종료해야 하는 I/O 오류를 구분한다.
    TUN, route, IP forwarding, nftables masquerade를 적용 역순으로 정리한다.
    TUN read는 non-blocking fd, poll, eventfd를 사용해 context 취소 시 종료한다.


남은 작업
---------

1. AEAD MTU 적용과 통합 검증

    IPv4 outer path MTU 1500을 기준으로 다음 overhead를 반영한다.

        outer IPv4 header = 20bytes
        UDP header        = 8bytes
        elevpn header     = 20bytes
        AEAD tag          = 16bytes

    TUN MTU와 MaxPayloadSize를 1436으로 변경한다.
    EC2에서 outer UDP packet이 1500 bytes를 넘지 않는지 확인한다.
    tun0의 평문 packet과 실제 NIC의 암호화된 UDP packet을 tcpdump로 비교한다.


2. replay window 보강

    현재 seq <= lastSeq 방식은 UDP packet이 순서대로 도착한다고 가정한다.
    packet 순서 역전을 허용하면서 중복 packet을 차단하는 sliding replay window를 검토한다.


3. handshake replay 방지

    캡처한 ALOHA를 반복 전송해 peer를 계속 생성하는 상황을 방지한다.
    client random 중복 검사, 시간 제한, rate limit 등의 handshake 정책을 검토한다.


4. route rollback 보강

    Route.Apply 중 bypass route를 여러 개 추가하다가 중간 실패하면,
    이미 추가된 route만 내부에서 rollback하도록 보강한다.


5. 테스트 보강

    protocol encode/decode, AEAD 인증 실패, sequence 검증에 대한 unit test를 추가한다.
    EC2 또는 Linux network namespace를 사용한 end-to-end test를 추가한다.
