Runtime Check List
==================

mage server, mage client 실행 후 현재 네트워크 상태를 확인하기 위한
명령어 모음이다.


Server
======

서버에서 확인할 핵심은 다음 네 가지다.

    - tun0가 생성되었는지
    - tun0에 VPN 주소가 붙었는지
    - IP forwarding이 켜졌는지
    - masquerade rule이 적용되었는지


1. TUN 인터페이스 확인
---------------------

    ip addr show dev tun0

확인할 수 있는 정보

    tun0 존재 여부
    tun0의 IP 주소
    인터페이스 UP 상태

예상 예시

    inet 10.77.0.1/24


2. 라우팅 테이블 확인
--------------------

    ip route show table main

확인할 수 있는 정보

    10.77.0.0/24 dev tun0 route 존재 여부
    기존 default route 유지 여부

예상 예시

    default via 192.168.139.1 dev eth0
    10.77.0.0/24 dev tun0 proto kernel scope link src 10.77.0.1

예시 해석

    10.77.0.0/24
        목적지 네트워크 대역이다.
        10.77.0.1, 10.77.0.2 같은 VPN 내부 주소들이 포함된다.

    dev tun0
        이 대역으로 가는 패킷은 tun0 인터페이스로 보낸다.

    proto kernel
        커널이 인터페이스 주소 설정을 보고 자동으로 만든 route다.
        예를 들어 tun0에 10.77.0.1/24를 붙이면 커널이 이 route를 만든다.

    scope link
        gateway를 거치지 않고 tun0에 직접 연결된 네트워크라는 뜻이다.

    src 10.77.0.1
        이 route를 통해 패킷을 보낼 때 기본 source IP로 10.77.0.1을 사용한다.

전체 의미

    서버는 10.77.0.0/24 VPN 내부 대역이 tun0에 직접 연결되어 있다고 본다.
    이 대역으로 보내는 패킷은 tun0로 나가고, source IP는 10.77.0.1을 쓴다.


3. IP forwarding 확인
---------------------

    cat /proc/sys/net/ipv4/ip_forward

확인할 수 있는 정보

    1 : IP forwarding 켜짐
    0 : IP forwarding 꺼짐

서버는 VPN 내부 패킷을 외부 인터페이스로 forwarding해야 하므로 1이어야 한다.


4. nftables masquerade 확인
---------------------------

    sudo nft list table ip vpnnat

확인할 수 있는 정보

    vpnnat table 존재 여부
    vpn-postrouting chain 존재 여부
    masquerade rule 존재 여부

기대하는 rule의 의미

    10.77.0.0/24에서 나온 패킷이 eth0로 나가면 masquerade

예상 예시

    table ip vpnnat {
            chain vpn-postrouting {
                    type nat hook postrouting priority srcnat; policy accept;
                    ip saddr 10.77.0.0/24 oifname "eth0" masquerade
            }
    }

예시 해석

    table ip vpnnat
        IPv4용 nftables table이다.
        elevpn이 VPN NAT 규칙을 담기 위해 만든 테이블이다.

    chain vpn-postrouting
        vpnnat 테이블 안의 체인이다.
        패킷이 외부로 나가기 직전에 처리되는 규칙이 들어 있다.

    type nat
        NAT용 체인이라는 뜻이다.

    hook postrouting
        라우팅 결정이 끝난 뒤, 패킷이 실제 인터페이스로 나가기 직전에 실행된다.

    priority srcnat
        source NAT 단계에서 실행된다는 뜻이다.
        즉 패킷의 출발지 주소를 바꾸는 시점이다.

    policy accept
        기본 정책은 accept다.
        규칙에 걸리지 않는 패킷도 기본적으로 통과시킨다.

    ip saddr 10.77.0.0/24 oifname "eth0" masquerade
        출발지 IP가 10.77.0.0/24 대역이고,
        나가는 인터페이스가 eth0이면,
        masquerade를 적용한다.

masquerade 적용 예시

    before
        src = 10.77.0.2
        dst = 8.8.8.8

    after masquerade
        src = 서버 eth0 IP
        dst = 8.8.8.8

전체 의미

    VPN 내부 대역 10.77.0.0/24에서 나온 패킷이 eth0로 나갈 때,
    서버의 eth0 주소로 source NAT를 적용한다.

전체 ruleset을 보고 싶으면 다음 명령을 사용한다.

    sudo nft list ruleset


5. UDP listen 확인
-----------------

    sudo ss -lunp | grep 9010

명령어 해석

    ss
        socket 상태를 보는 명령어다.

    -l
        listening socket만 보여준다.

    -u
        UDP socket만 보여준다.

    -n
        주소와 포트를 숫자로 보여준다.
        예를 들어 service 이름 대신 9010을 그대로 표시한다.

    -p
        어떤 프로세스가 socket을 가지고 있는지 보여준다.
        보통 sudo가 필요하다.

    grep 9010
        결과 중 9010 포트가 들어간 줄만 본다.

확인할 수 있는 정보

    서버가 UDP 9010 포트에서 listen 중인지
    elevpn 프로세스가 해당 socket을 가지고 있는지

예상 예시

    UNCONN 0 0 *:9010 *:* users:(("elevpn",pid=93257,fd=5))

예시 해석

    UNCONN
        UDP socket 상태다.
        UDP는 TCP처럼 연결 상태가 없기 때문에 보통 UNCONN으로 보인다.

    0 0
        수신 큐와 송신 큐 크기다.
        현재 쌓인 패킷이 없다는 뜻으로 보면 된다.

    *:9010
        모든 로컬 IP의 UDP 9010 포트에서 패킷을 받을 준비가 되어 있다.
        0.0.0.0:9010과 비슷하게 이해하면 된다.

    *:*
        특정 상대 주소와 연결되어 있지 않다는 뜻이다.
        UDP listen socket에서는 자연스러운 상태다.

    users:(("elevpn",pid=93257,fd=5))
        이 socket을 가진 프로세스 정보다.
        프로세스 이름은 elevpn, PID는 93257, file descriptor는 5다.

전체 의미

    elevpn 프로세스가 UDP 9010 포트에서 모든 인터페이스를 대상으로
    패킷을 받을 준비를 하고 있다.


Client
======

클라이언트에서 확인할 핵심은 다음 네 가지다.

    - tun1이 생성되었는지
    - tun1에 VPN 주소가 붙었는지
    - VPN 서버 IP 예외 route가 있는지
    - default route가 tun1로 바뀌었는지


1. TUN 인터페이스 확인
---------------------

    ip addr show dev tun1

확인할 수 있는 정보

    tun1 존재 여부
    tun1의 IP 주소
    인터페이스 UP 상태

예상 예시

    inet 10.77.0.2/32


2. 라우팅 테이블 확인
--------------------

    ip route show table main

확인할 수 있는 정보

    VPN 서버 IP /32 예외 route 존재 여부
    default route가 tun1로 변경되었는지

예상 형태

    <server-ip>/32 via <real-gateway> dev <real-nic>
    default dev tun1

예시

    203.0.113.10/32 via 192.168.139.1 dev eth0
    default dev tun1


3. 서버 endpoint route 확인
---------------------------

    ip route get <server-ip>

확인할 수 있는 정보

    VPN 서버로 가는 UDP 패킷이 실제 NIC로 나가는지

기대 형태

    <server-ip> via <real-gateway> dev <real-nic>

예시

    203.0.113.10 via 192.168.139.1 dev eth0


4. 일반 트래픽 route 확인
------------------------

    ip route get 8.8.8.8

확인할 수 있는 정보

    일반 인터넷 트래픽이 tun1로 들어가는지

기대 형태

    8.8.8.8 dev tun1


5. UDP socket 확인
-----------------

    sudo ss -uapn | grep elevpn

확인할 수 있는 정보

    클라이언트 UDP socket 상태
    서버 endpoint와 UDP 연결이 잡혀 있는지


Short Version
=============

서버에서 자주 볼 명령어

    ip addr show dev tun0
    ip route show table main
    cat /proc/sys/net/ipv4/ip_forward
    sudo nft list table ip vpnnat
    sudo ss -lunp | grep 9010

클라이언트에서 자주 볼 명령어

    ip addr show dev tun1
    ip route show table main
    ip route get <server-ip>
    ip route get 8.8.8.8
    sudo ss -uapn | grep elevpn
