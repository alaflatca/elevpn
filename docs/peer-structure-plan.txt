Peer Structure Plan
===================

이 문서는 단일 client 통신 테스트에 성공한 이후,
server 쪽 구조를 peer 기반으로 바꾸기 위한 다음 단계를 정리한 것이다.


현재 상태
---------

현재 server는 테스트를 위해 peerAddr 하나만 가지고 있다.

의미

    마지막으로 UDP packet을 보낸 client 주소를 저장한다.
    server가 tun0에서 packet을 읽으면 그 주소로 다시 UDP 전송한다.

이 구조는 단일 client 테스트에는 충분하다.

검증된 것

    client TUN read
    client UDP send
    server UDP receive
    server TUN write
    server ip_forward
    server masquerade
    server TUN read
    server UDP send back
    client UDP receive
    client TUN write


현재 구조의 한계
----------------

peerAddr 하나만 저장하는 방식은 여러 client를 지원할 수 없다.

문제점

    client가 2명 이상이면 마지막 client 주소로 덮어써진다.
    어떤 VPN IP가 어떤 UDP 주소에 대응되는지 알 수 없다.
    tun0에서 읽은 packet을 어느 client에게 보내야 하는지 판단하기 어렵다.
    인증, 암호화, keepalive, last seen 같은 상태를 붙일 위치가 부족하다.

핵심 문제

    UDP 주소만으로는 VPN peer를 충분히 표현할 수 없다.
    VPN 내부 IP와 UDP endpoint를 연결해야 한다.


다음 목표
---------

server가 peer를 명시적으로 관리하도록 바꾼다.

핵심 방향

    peerAddr 단일 필드를 제거한다.
    Peer 타입을 만든다.
    UDP address 기준 조회와 VPN IP 기준 조회를 분리한다.
    tunToUdp에서는 destination VPN IP를 보고 보낼 peer를 선택한다.
    udpToTun에서는 source VPN IP와 UDP address를 보고 peer를 등록 또는 갱신한다.


추천 구조
---------

Server가 관리할 상태

    peersByAddr
        UDP address 기준 peer 조회용 map

    peersByVPNIP
        VPN 내부 IP 기준 peer 조회용 map

    mutex
        peer map 동시 접근 보호용

Peer가 가질 정보

    UDPAddr
        client의 실제 UDP endpoint

    VPNIP
        client의 VPN 내부 IP

    LastSeen
        마지막으로 packet을 받은 시각

    Session 또는 Key
        나중에 인증/암호화를 붙일 때 사용할 상태


udpToTun 흐름
-------------

역할

    client에서 UDP로 받은 packet을 server tun0에 넣는다.
    동시에 peer 정보를 등록 또는 갱신한다.

흐름

    1. UDP packet 수신

        conn.ReadFromUDP()

    2. UDP address 확인

        packet을 보낸 client의 실제 endpoint를 얻는다.

    3. IP packet의 source VPN IP 파싱

        client TUN에서 나온 packet이므로 source IP는 client의 VPN IP다.

        예시

            src = 10.77.0.2
            dst = 104.26.13.205

    4. peer 등록 또는 갱신

        UDP address와 VPN IP를 연결한다.
        LastSeen을 갱신한다.

    5. packet을 tun0에 write

        server kernel이 이 packet을 forwarding/NAT 처리할 수 있게 한다.


tunToUdp 흐름
-------------

역할

    server tun0에서 읽은 packet을 올바른 client peer에게 UDP로 보낸다.

흐름

    1. tun0에서 IP packet 읽기

        tunDevice.Read()

    2. IP packet의 destination VPN IP 파싱

        외부에서 돌아온 응답 packet은 client VPN IP로 향한다.

        예시

            src = 104.26.13.205
            dst = 10.77.0.2

    3. destination VPN IP로 peer 조회

        peersByVPNIP["10.77.0.2"]로 peer를 찾는다.

    4. peer가 있으면 UDP 전송

        conn.WriteToUDP(packet, peer.UDPAddr)

    5. peer가 없으면 packet 처리 불가

        테스트 단계에서는 drop하고 로그만 남겨도 된다.


왜 destination VPN IP 기준이 필요한가
------------------------------------

server가 tun0에서 읽는 packet은 client로 되돌려 보내야 할 packet이다.

server가 이 packet을 어느 UDP address로 보낼지 알려면,
packet의 destination IP가 어느 peer의 VPN IP인지 알아야 한다.

예시

    packet dst = 10.77.0.2

    peersByVPNIP에서 10.77.0.2를 찾는다.

    찾은 peer의 UDPAddr로 WriteToUDP한다.


단계별 변경 계획
----------------

1. Peer 타입 추가

    UDPAddr
    VPNIP
    LastSeen

2. Server에 peer map 추가

    peersByAddr
    peersByVPNIP
    mutex

3. udpToTun에서 peer 등록

    ReadFromUDP로 UDP address를 얻는다.
    IP packet source 주소를 파싱한다.
    UDP address와 VPN IP를 연결한다.

4. tunToUdp에서 peer 선택

    tun0에서 읽은 packet의 destination 주소를 파싱한다.
    peersByVPNIP에서 peer를 찾는다.
    찾은 peer의 UDPAddr로 WriteToUDP한다.

5. 단일 peerAddr 필드 제거

    더 이상 마지막 client 주소 하나에 의존하지 않는다.

6. 이후 확장

    인증
    암호화
    keepalive
    peer timeout
    client별 virtual IP 할당


주의할 점
---------

IP packet 파싱은 server peer 구조의 핵심이다.

udpToTun에서는 source IP가 중요하다.

    이 packet을 보낸 client의 VPN IP를 알기 위해서다.

tunToUdp에서는 destination IP가 중요하다.

    이 packet을 받을 client peer를 찾기 위해서다.

peer map은 여러 goroutine에서 접근하므로 mutex가 필요하다.

    udpToTun은 peer를 등록 또는 갱신한다.
    tunToUdp는 peer를 조회한다.


현재 구조에서 다음 구조로 바뀌는 핵심
------------------------------------

현재

    server.peerAddr 하나
    마지막 client에게만 응답

변경 후

    server.peersByAddr
    server.peersByVPNIP
    packet의 IP header를 보고 peer 결정

핵심 변화

    UDP address 중심에서
    VPN IP와 UDP address를 연결한 peer 중심으로 이동한다.
