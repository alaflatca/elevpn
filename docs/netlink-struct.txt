AF_Netlink
    - NETLINK_NETFILTER : netfilter 서브시스템용 
    - NETLINK_ROUTE     : 라우팅, 링크, 주소 제어용

* 여기서 Payload란 Nelink Header를 제외한 나머지들을 Payload 라고 함 ( Payload = B + C )

=============================
1. 송신 데이터 구조 (Request)
=============================

A.  Netlink Header (16 bytes)
    [Length   (4 bytes)] *이 전체 메시지(헤더 + 페이로드)의 총 길이
    [type     (2 bytes)] *메시지의 종류(예: 규칙 생성, 테이블 생성 등)
    [Flags    (2 bytes)] *요청(REQUEST), 응답(ACK) 옵션
    [Sequence (4 bytes)] *내가 붙인 일련번호, 나중에 답장을 매칭할 떄 쓰임
    [PortID   (4 bytes)] *커널이 보내면 보통 0, 유저 공간 소켓은 자기 port ID를 가짐.

=========================================================================================
B.  Netfilter Header (4 bytes)  *[nfgenmsg: family, version, res_id]
    [Family    (1 bytes)] *netfilter protocol family (예: IPv4/IPv6 familyh)
    [Version   (1 bytes)] *넷링크 버전이며 보통 0
    [Res ID    (2 bytes)] *나중을 위해 비워둔 예약 공간(0,0)

OR

B. ROUTE Header (12 bytes) *[rtmsg: family, dst_len, src_len, tos, table, ...]
    [Family     (1 byte)] *AF_INET / AF_INET6
    [dst_len    (1 byte)] *목적지 prefix 길이 (/32, 24, default면 0)
    [src_len    (1 byte)] *source prefix 길이
    [tos        (1 byte)] *TOS/DS field
    [table      (1 byte)] *어느 routing table인지 (main등)
    [protocol   (1 byte)] *route가 어디서 왔는지 (static, kernel 등)
    [scope      (1 byte)] *route scope
    [type       (1 byte)] *unicast 등
    [flags      (4 byte)] *route flags

=========================================================================================

C. Attributes  (실제 데이터 - TLV 방식)
    [Attr Length (2 bytes)] *이 속성의 길이
    [Attr Type   (2 bytes)] *netfilter의 경우 테이블 이름인지, 체인 이름인지 등의 종류, route의 경우 목적지_prefix, gateway, oif
    [Value       (가변)]     *실제 값(예:"vpnnat"이라는 이름)이 들어감
    [Padding     (전체 데이터가 길이가 4의 배수로)]

* 송신 시 페이로드
    - [Netfilter Header] + [Attributes]
    - [Route Header] + [Attributes]
    = B + C



=============================
2. 수신 데이터 구조 (Response)
=============================

A. Netlink Header (16 bytes)
    [Length    (4 bytes)] *응답 메시지 전체 길이
    [type      (2 bytes)] *2(NLMSG_ERROR), 24(RTM_NEWROUTE), 타입에 따라 페이로드 구조가 달라짐
    [Flags     (2 bytes)] *응답 관련 플래그
    [Sequence  (4 bytes)] *내가 보냈던 요청의 일련번호가 그대로 돌아옴
    [PortID    (4 bytes)] *내 프로세스 ID

*Header의 type에 따라 Payload가 달라짐

B. type = 2, Error Payload 구조로 읽어야됨
    [Errno     (4 bytes)] *0이면 성공, 음수면 실패
    [Original Header (16 bytes)] *요청했을때 헤더를 돌려줌 (발신자 확인 가능 및 이 요청에 대한 답장이라는걸 확인 시켜주는 용도)

B. type = 24, Route Payload 구조로 읽어야됨
 ROUTE Header (12 bytes)
    [Family     (1 byte)]
    [dst_len    (1 byte)]
    [src_len    (1 byte)]
    [tos        (1 byte)]
    [table      (1 byte)]
    [protocol   (1 byte)]
    [scope      (1 byte)]
    [type       (1 byte)]
    [flags      (4 byte)]

B. type = 20, InetDiagMsg (72 bytes) (이 구조는 c를 무시해도됨),SOCK_DIAG_BY_FAMILY
 InetDiagMsg Header (4 byte)
    [Family      1 byte]
    [State       1 byte]
    [Timer       1 byte]
    [Retrans     1 byte]
 SockID (48 byte)
    [Source Port       2 bytes]  big endian
    [Destination Port  2 bytes]  big endian
    [Source IPv4       4 bytes]  IPv4일 때 앞 4 bytes 사용
    [Source Padding   12 bytes]  IPv6 자리 맞춤
    [Destination IPv4  4 bytes]  IPv4일 때 앞 4 bytes 사용
    [Destination Pad  12 bytes]
    [Interface         4 bytes]
    [Cookie            8 bytes]
 Extra (20 byte)
    [Expires   4 bytes]
    [RQueue    4 bytes]
    [WQueue    4 bytes]
    [UID       4 bytes]
    [Inode     4 bytes]

**
payload[0]      family
payload[1]      state

payload[4:6]    source/local port
payload[6:8]    destination/remote port

payload[8:12]   source/local IPv4
payload[24:28]  destination/remote IPv4
**

C. Attributes
    [Attr Length (2 bytes)]
    [Attr Type   (2 bytes)]
    [Value       (가변)]
    [Padding     (전체 데이터가 길이가 4의 배수로)]



※ 페이로드란 Netlink Header(앞부분 16바이트)를 제외한 나머지 모든 데이터 부위를 말한다.


※ 넷링크 메세지란: nlmsgHdr(netlink header) + payload(error,route header + attrs) 

NLM_F_DUMP 플래그 사용 X, unix.RecvFrom을 사용하면, 단일 넷링크 메세지 응답
[Header][RouteHeader][Attrs...][Padding]

NLM_F_DUMP 플래그 사용 O, unix.RecvFrom을 사용하면, 다중 넷링크 메세지 응답
[Header][RouteHeader][Attrs...][Padding][Header][RouteHeader][Attrs...][Padding][Header][RouteHeader][Attrs...][Padding]
[Header][RouteHeader][Attrs...][Padding][Header][RouteHeader][Attrs...][Padding]
